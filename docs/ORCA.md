# Orchestra + Orca: полная настройка и ежедневная работа

Всё выполняется **на Mac mini**: там диск с проектами, Orca-сервер, служба Orchestra, вход в Claude и ключи провайдеров. MacBook — только окно в Orca через shared server, на нём ничего настраивать не нужно, кроме пункта 9.

Команды из этой инструкции запускаются в обычном Терминале на Mac mini или в терминале Orca, открытом на Mac mini.

---

## 1. Отправить на GitHub то, что уже сделано (один раз, сейчас)

```bash
cd ~/Developer
for r in "Orchestra" "Work/app-a" "Work/site-b" "Work/data-c" "Work/workers"; do
  echo "== $r"; (cd "$r" && git push)
done
```

После push в site-b сайт перевыложится автоматически. Код не менялся, так что это безопасно.

У папки `Work` (общая wiki) remote пока нет. Создайте на GitHub приватный репозиторий `work-wiki`, затем:

```bash
cd "~/Developer/Work"
git remote add origin https://github.com/<your-account>/work-wiki.git && git push -u origin main
```

## 2. Установить Orchestra (один раз)

```bash
cd "~/Developer/Orchestra"
npm install
npm run build
npm link
which orchestra-memory orchestra-serve orchestra-mcp   # должны найтись все три
```

Если `npm link` просит права администратора, переведите глобальные пакеты npm в домашнюю папку и повторите `npm link`:

```bash
npm config set prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zprofile && source ~/.zprofile
```

Проверка: `npm run smoke` (около минуты, без сети и ключей). Все наборы должны закончиться словом OK.

## 3. Войти в модели (один раз)

- **Claude Pro:** `claude`, затем `/login`, выйти через `/exit`. Проверка: `claude auth status`.
- **ChatGPT (по желанию):** `codex login`. Проверка: `codex login status`.

## 4. Запуск Orchestra и режимы работы

**Проще всего — файл `Orchestra.command` в папке Orchestra.** Двойной клик в Finder открывает Терминал с диагностикой: что установлено, работает ли служба, какие проекты найдены и подключена ли в них Orchestra. Ниже — меню:

| Пункт | Режим | Что происходит |
|---|---|---|
| 1 | **Orca и Orchestra вместе** | служба Orchestra работает в фоне и стартует при входе в систему; в каждом проекте Claude Code в терминале Orca видит Orchestra |
| 2 | **Только Orca** | служба выключена, из проектов убрано подключение Orchestra; агенты в Orca работают сами. Память и wiki продолжают работать |
| 3 | **Только Orchestra** | служба и панель работают, в проектах Orca Orchestra не подключена |
| 4 | **Отменить** | вернуть всё как было до последнего применения |
| 5 | Открыть панель | сразу с токеном |
| 6 | Проекты | где искать репозитории (по умолчанию `~/Developer`) |

Перед каждым изменением показывается список того, что будет сделано, и вопрос «Применить?». Заодно файл чинит мелочи в проектах: включает git-хуки памяти и убирает «изменения», которые на самом деле только смена прав файлов.

То же самое есть в панели Orchestra: вкладка **«Диагностика»** (или кнопка режима в правом верхнем углу). Если в панели выбрать «Только Orca», служба остановится и панель перестанет отвечать — включить её снова можно через `Orchestra.command`.

Из терминала: `orchestra-doctor` (меню), `orchestra-doctor --json`, `orchestra-doctor --mode together --yes`, `orchestra-doctor --undo --yes`.

Ниже — то же самое вручную, если нужно понять, что делает файл.

**4.1. Пробный запуск вручную** (проверить, что всё работает):

```bash
orchestra-serve
```

В консоли появится ссылка вида `http://127.0.0.1:7777/?token=…`. Откройте её в браузере — это панель Orchestra. Остановить: `Ctrl+C`.

**4.2. Постоянная работа в фоне** (один раз):

```bash
orchestra-serve --print-token        # токен доступа — сохраните в менеджер паролей
orchestra-serve --install-launchd    # записывает автозапуск
launchctl unload ~/Library/LaunchAgents/dev.orchestra.serve.plist 2>/dev/null
launchctl load -w ~/Library/LaunchAgents/dev.orchestra.serve.plist
```

Проверка, что служба работает: `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7777/` отвечает `200`. Лог: `~/Library/Application Support/Orchestra/logs/serve.log`.

Перезапуск (например, после обновления Orchestra): `launchctl kickstart -k gui/$(id -u)/dev.orchestra.serve`.
Остановить совсем: `launchctl unload -w ~/Library/LaunchAgents/dev.orchestra.serve.plist`.

**4.3. Открыть панель.** Панель пускает только по ссылке с токеном. Проще всего одной командой:

```bash
open "http://127.0.0.1:7777/?token=$(orchestra-serve --print-token)"
```

Браузер запомнит токен, дальше хватит `http://127.0.0.1:7777/`. Если вместо панели видите «Orchestra: откройте ссылку с токеном» — вы открыли адрес без токена (или в другом браузере, в окне инкогнито): выполните команду выше ещё раз.

Затем **Настройки → Подключения**:

1. Добавьте **Claude (подписка)**. Это оркестратор, он планирует и ревьюит.
2. Добавьте хотя бы одного исполнителя с ключом: **DeepSeek** (дешевле всех), GLM, Kimi, Qwen.
3. Подождите, пока карточки загорятся зелёным. Жёлтый — нет денег или исчерпан лимит, красный — не подключено.

**С MacBook.** Служба должна слушать адрес Tailscale: выполните `orchestra-serve --host $(tailscale ip -4) --install-launchd`, затем две команды `launchctl` из 4.2, и откройте на MacBook `http://<адрес Tailscale Mac mini>:7777/`. В командах `claude mcp add` (пункт 7) тогда тоже этот адрес вместо `127.0.0.1`.

**Настольное приложение** (`npm start` в папке Orchestra) — то же самое в отдельном окне, но только на этом компьютере и без MCP для Orca. Службу и приложение одновременно не запускайте.

## 5. Память проекта в репозиториях

Уже включена в `Work`, `app-a`, `site-b`, `data-c` и `workers`. Для нового проекта:

```bash
cd <папка проекта>
orchestra-memory init --project "<имя>"
git add -A && git commit -m "Память проекта"
```

Что это даёт:

| Файл | Для кого | Что в нём |
|---|---|---|
| `wiki/` | для вас и агентов | описание проекта, текущее состояние, решения |
| `wiki/JOURNAL.md` | для вас | журнал микросессий, новые записи сверху |
| `CHANGELOG.md` | для людей | выжимка по этапам |
| `.memory/facts.json`, `logic.json` | для ИИ | факты и решения с причинами |
| `.memory/log/*.jsonl` | для ИИ | подробный лог всех действий |
| `CLAUDE.md`, `AGENTS.md` | для агентов | правила: смотреть память, вести wiki, закрывать микросессии |
| `.claude/settings.json` | Claude Code | хуки: память к каждому запросу, лог правок, напоминание через 35 минут |
| `.githooks/` | git | память, wiki и CHANGELOG уходят в каждый коммит |

**Хуки git.** После `git clone` на другом компьютере хуки надо включить заново одной командой: `git config core.hooksPath .githooks` (или снова `orchestra-memory init`). Git не переносит эту настройку.

Проверка: `git config core.hooksPath` отвечает `.githooks`, а `orchestra-memory status` показывает число фактов и решений.

Остальные проекты пока без памяти. У одного из них свой хук, который пишет `wiki/actions.jsonl`. Прежде чем включать память там, решите, какой лог оставить.

## 6. Проекты в Orca

- Добавьте в группу **Work** папки `app-a`, `site-b`, `data-c`, `workers` и саму `Work` (общая wiki). Путь: `~/Developer/Work/...`.
- **Работайте в основной папке на ветке `main`, без worktree Orca.** Вы один и ведёте один поток работы. В worktree память и журнал разъезжаются по веткам и потом конфликтуют при слиянии.
- **Один агент на один репозиторий в каждый момент.** Два агента в одной папке мешают друг другу. В разных репозиториях — сколько угодно.
- Один и тот же терминал Orca не держите открытым одновременно на Mac mini и MacBook: это известная ошибка Orca.

## 7. Подключить Orchestra к Claude Code (один раз в каждом репозитории)

Это делает пункт 1 в `Orchestra.command` сразу для всех проектов. Вручную:

В терминале Orca, в папке проекта:

```bash
claude mcp add --transport http orchestra "http://127.0.0.1:7777/mcp?repo=$(pwd)" \
  --header "Authorization: Bearer <токен из пункта 4>"
claude mcp list          # orchestra: connected
```

Настройка сохраняется для этой папки в `~/.claude.json`, а не в репозитории, так что токен в git не попадёт. Если служба слушает адрес Tailscale, подставьте его вместо `127.0.0.1`.

После этого Claude в этой папке может раздать задачу дешёвым исполнителям: *«раздай это через Orchestra, проверь diff и слей»*. Или отдать её целиком: *«отдай автопилоту Orchestra»*. Всё видно в панели Orchestra и остаётся в истории.

## 8. Как работать каждый день

1. **Открыть терминал проекта в Orca → `claude`.** При старте Claude получает память проекта: прошлую сессию, последние решения, число фактов. С каждым вашим сообщением хук подмешивает подходящие факты и решения.
2. **Поставить задачу — командой `/orchestra`.** Напишите в Claude `/orchestra <что нужно сделать>`. Claude сначала смотрит память проекта и wiki (что уже сделано и почему), затем показывает бриф: цель, что известно, границы, подзадачи, «готово, когда», как проверить, вопросы к вам. Вы утверждаете или правите бриф и выбираете, как делать: **А** — раздать исполнителям через Orchestra (Claude проверяет и сливает), **Б** — отдать Orchestra целиком (автопилот), **В** — Claude делает сам в этой сессии. Пока Orchestra выключена, доступен только вариант В. В конце — отчёт, запись в память и журнал. Мелкие правки можно просить и без команды.
3. **Через 35 минут** Claude получит напоминание и закроет микросессию: короткая запись для вас в `wiki/JOURNAL.md`, подробная для ИИ — в `.memory/log/`. Можно попросить в любой момент: *«закрой микросессию»*. Если забыли, её закроет выход из Claude или следующий коммит.
4. **«Дай свежую выжимку»** — краткий пересказ последних записей лога.
5. **Конец этапа:** *«сделай CHANGELOG этапа»* — записи в `CHANGELOG.md` по разделам Added, Fixed, Security, без мелких деталей.
6. **Прод и утверждение — вашими фразами.** Агент не может сам выложить сайт, применить миграцию к боевой базе или поменять секреты: сторож остановит команду. Когда агент попросит, напишите **«разрешаю прод»** — это окно на 20 минут в этом проекте («запрещаю прод» — закрыть раньше). Бриф из `/orchestra` становится утверждённым, когда вы пишете **«утверждаю»**; если бриф потом изменится, агент попросит утвердить снова.
7. **Коммит** — кнопкой в Orca, агентом или `git commit`. Память, wiki и CHANGELOG добавятся сами. Если код менялся, а wiki нет, появится предупреждение.
8. **Push.** Если push остановился со словами «память дописана отдельным коммитом», нажмите push ещё раз. Или сразу `orchestra-memory push`.
   - **site-b:** push в `main` сразу выкладывает сайт в прод.
   - **app-a:** деплой только вручную, через GitHub Actions.
   - **data-c:** пока только скриптом с Мака.

Прод, миграции D1 и боевые флаги агент меняет только после вашего явного «да». Это записано в правилах каждого проекта.

### Льготное время (DeepSeek)

DeepSeek вне часов пик вдвое дешевле. Дорого по будням с 04:00 до 07:00 и с 09:00 до 13:00 по Москве, в остальное время и в выходные — льготно. Текущий тариф виден в верхней строке панели.

- Кнопка **«☾ В льготное время»** под «Запустить» ставит задачу на ближайшее льготное окно от трёх часов (по будням обычно 13:00). До старта ничего не тратится. Запланированное видно в блоке «Запланировано»: там же «Запустить сейчас» и «Отменить».
- В таком запуске задачи DeepSeek не начинаются в часы пик, а ждут их окончания. Задачи других исполнителей идут как обычно.
- В Claude Code в Orca: *«отдай автопилоту Orchestra в льготное время»*.
- Расход считается по фактическому тарифу в момент работы.

## 9. MacBook

На MacBook ставить ничего не нужно, если вы работаете через Orca shared server: терминалы и файлы живут на Mac mini. Если когда-нибудь будете клонировать репозитории прямо на MacBook, повторите там пункты 2 и 3 и выполните `git config core.hooksPath .githooks` в каждом репозитории.

## 10. Готовые задания

В `Work/wiki/tasks/` лежат задания по проектам, например сквозная публикация, форма письма, соглашение о неразглашении для всего портала. Как запустить:

- откройте терминал нужного репозитория в Orca и запустите `claude`;
- вставьте: *«Прочитай ../wiki/tasks/README.md и ../wiki/tasks/<файл> и выполни задание»*;
- Задания для `site-b` и `app-a` можно вести параллельно в двух терминалах, общее для всего портала — после них.

## 11. Если что-то не работает

| Что не так | Что проверить |
|---|---|
| В журнал ничего не пишется | `which orchestra-memory` в терминале; если пусто — пункт 2 |
| Хуки не срабатывают при коммите из Orca | `git config core.hooksPath` должен быть `.githooks`. Хук сам добавляет в PATH `/opt/homebrew/bin`, `/usr/local/bin` и `~/.npm-global/bin`. Если npm стоит в другом месте, укажите путь в `.githooks/pre-commit` |
| Агент пишет «Сторож прода: …» | Так и задумано: команда меняет прод. Если согласны — напишите «разрешаю прод». Сторож выключается в `.memory/config.json` → `prodGuard.enabled: false` (не рекомендуется) |
| Нужно закоммитить без хуков | `ORCHESTRA_MEMORY_OFF=1 git commit …` |
| Claude не видит Orchestra | `claude mcp list`; служба жива: `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7777/` отвечает 200 |
| Карточка подключения жёлтая или красная | Настройки → Подключения → «Проверить» |
| «Orchestra: откройте ссылку с токеном» | Открыт адрес без токена: `open "http://127.0.0.1:7777/?token=$(orchestra-serve --print-token)"` |
| Лог службы | `~/Library/Application Support/Orchestra/logs/serve.log` |

Подробнее: [SETUP.md](SETUP.md) (установка и подключения), [MEMORY.md](MEMORY.md) (как устроена память).
