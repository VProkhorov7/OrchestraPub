# Инварианты: Orchestra

То, что не должно стать неправдой **никогда**. Агенты сверяют с этим списком каждое изменение, Orchestra даёт его каждому исполнителю и проверяет по нему diff перед слиянием.

Как писать: одна строка — одно утверждение «никогда …» или «всегда …»; в скобках — чем это проверяется (тест, хук, CI). Тест, который стережёт инвариант, готов, только когда краснеет при намеренном проломе именно этого места. Менять или снимать инвариант — только решением с причиной (`orchestra-memory add-decision`).

- Прод меняется только после явного разрешения владельца (сторож прода).
- Секреты не попадают в код, wiki и память — только их имена.
- Миграции базы только добавляются; применённую миграцию не правят (новая миграция вместо правки).
- Слияние и отбрасывание из панели никогда не выполняются без подтверждения владельца (проверено чтением `renderer/attention.js`; для merge/discard теста нет, нет jsdom: при правке этого файла проверять руками).
- Продолжение из панели никогда не запускается без подтверждения владельца и не уходит вторым вызовом во время запроса (`smoke-attention-ui`: «confirm declined → continueTask not called», «double click while busy: no second call, no second confirm», «chosen worker vanished: nothing started», «fresh options: confirm shows the new (paid) forced worker and cap»; логика в `renderer/attention-logic.js`). Не покрыта тестами DOM-обвязка `attWireCont` и отрисовка формы в `renderer/attention.js`: при правке проверять руками в браузере.
- «Слить» и «Отбросить» никогда не меняют статус задачи в `run.json`, если репозиторий запуска не найден: вместо этого ответ «Репозиторий не найден, ничего не сделано» (`smoke-serve`: «merge/discard with a missing repo», краснеет без `fs.existsSync` в `Hub.merge/discard`).
- Одну и ту же старую задачу нельзя продолжить из панели дважды: ни вторым кликом, ни двумя почти одновременными (`smoke-continue`: «saved task continued twice», «parallel clicks: one started, one refused»; краснеют без `Hub.continuedBy` и без Set `continuing`). Каждое продолжение, в том числе с чистого листа, несёт связь `continuedFrom` на старую задачу (`smoke-continue`: «clean start: linked»).
- Продолжение из панели никогда не запускает автоповтор с чистого листа, если рабочая папка не была создана: задача уходит владельцу (`smoke-continue`: «vanished branch: no automatic retry», «escalated to the owner»).
- Аргументы git из `run.json` (`baseSha`, ветка) никогда не передаются в команду без проверки: `baseSha` только hex 7–40 знаков, ветка не начинается с «-», перед диапазоном `--end-of-options` (`smoke-serve`: «unsafe baseSha: no file written by git»).
- Файл `run.json` старого запуска не меняется продолжением задачи; пункт закрывается связью, а не правкой старого файла (`smoke-continue`: «old run.json unchanged»).
