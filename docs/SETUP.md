## 1. Что понадобится

| Что | Зачем | Как проверить |
|---|---|---|
| Node.js 20+ | запуск Orchestra | `node -v` |
| git | worktree и слияния | `git --version` |
| Claude Code | на нём работают все исполнители; с подпиской ещё и оркестратор | `claude --version`, вход: `claude`, затем `/login` |
| Codex CLI (необязательно) | оркестратор на подписке ChatGPT | `codex --version`, вход: `codex login` |
| Ключ хотя бы одного дешёвого провайдера | исполнители | DeepSeek, z.ai (GLM), Moonshot (Kimi), MiniMax, Alibaba (Qwen), OpenRouter |
| [CodexBar](https://github.com/steipete/CodexBar) (необязательно) | проценты лимитов подписок на карточках | `codexbar usage` |
| [Tailscale](https://tailscale.com) (для сервера) | доступ к службе с других машин | `tailscale ip -4` |

## 2. Установка

```bash
git clone https://github.com/VProkhorov7/OrchestraPub.git
cd Orchestra
npm install
npm run smoke        # необязательно: автотесты без ключей и сети, около минуты
npm run build && npm link   # команды orchestra-memory, orchestra-mcp, orchestra-serve в PATH
```

`npm link` нужен на каждом компьютере, где вы правите код (Mac mini и MacBook): через команду `orchestra-memory` git-хуки и Claude Code ведут память проекта. Как её включить в репозитории: [MEMORY.md](MEMORY.md).

Дальше один из двух вариантов:

- **Настольное приложение**: `npm start`. Удобно, если всё работает на одном компьютере.
- **Служба**: `npm run serve`. Удобно для домашнего сервера (раздел 5).

Одновременно на одной машине запускайте что-то одно. Данные у них общие (настройки, история): на macOS `~/Library/Application Support/Orchestra/`, на Linux `~/.config/Orchestra/`.

> Node 26 и новее: если `npm install` не скачал Electron, выполните `npm install-scripts approve electron && node node_modules/electron/install.js`. Для службы Electron не нужен.

## 3. Подключения

**Настройки → Подключения.** В выпадающем списке всё, что ещё не добавлено. Нажмите «Добавить», затем «Настроить» на карточке, введите ключ, «Проверить».

| Группа | Что есть | Как платите |
|---|---|---|
| Подписки | Claude (Pro/Max, через Claude Code), ChatGPT (через Codex CLI) | фиксированная цена, лимиты окнами 5 ч и неделя |
| API | Claude API, DeepSeek, GLM, Kimi, MiniMax, Qwen, OpenRouter, «своё» (любой Anthropic-совместимый адрес) | за токены, цены вводятся на карточке |
| Coding-планы | GLM Coding Plan, MiniMax Token Plan | фиксированная цена, кредиты плана |

Цвет карточки:

- 🟢 **работает**: ключ или вход принят, сервис отвечает.
- 🟡 **подключено, нет денег**: ответ «insufficient balance», нулевой баланс, лимит подписки на 100%.
- 🔴 **не подключено**: нет ключа, ключ отклонён, не выполнен вход, программа не установлена.

На каждой карточке:

- **«брать задачи»** — может ли подключение быть исполнителем. Подписка Claude тоже может, но тогда она тратит тот же лимит, что и оркестратор.
- **Роли** — какие задачи ему можно давать. Без ролей можно любые.
- **Цены за 1M токенов и «лимит $ за запуск».**
- **Заметки для оркестратора** — чем этот исполнитель хорош. Оркестратор читает их при выборе.

Gemini напрямую не подключается (у него нет Anthropic-совместимого адреса): пошаговая инструкция с локальным мостом — [GEMINI-BRIDGE.md](GEMINI-BRIDGE.md).

Id моделей у провайдеров часто меняются. Если карточка красная с ошибкой «модель не найдена», исправьте id модели на карточке.

**Условия coding-планов.** Некоторые планы запрещают автоматическое использование (так прямо написано у Qwen Coding Plan). Для Qwen используйте ключ с оплатой за токены. Условия остальных планов проверьте сами.

## 4. Первая задача

1. **Репозиторий**: путь к git-репозиторию без незакоммиченных изменений. Оркестратор работает с текущей веткой.
2. **Задание**: опишите, что нужно, или прикрепите `.md` или `.txt`.
3. **«Распределить автоматически»**:
   - появляется блок «Кто будет планировать и вести задачу» с оценкой сложности, рекомендацией и причиной;
   - «Утвердить» или выберите другую модель в списке;
   - выбранная модель составляет план, он открывается на вкладке «План», его можно править: название, роль, исполнитель, бриф.
4. **«Запустить по плану»**: вкладки «Оркестратор» (ход рассуждений и вызовы) и «Воркеры» (каждый исполнитель вживую, его лог, diff, расход).
5. В конце появляется отчёт. Слитые задачи лежат в вашей ветке отдельными merge-коммитами. Неслитые ветки остаются: их можно слить или отбросить вручную на карточке задачи, в том числе потом из «Истории».

Нужно ли спрашивать про модель, настраивается здесь: **Настройки → Оркестратор → «Выбор модели для каждой задачи»**:

- спрашивать меня (по умолчанию);
- брать рекомендацию молча;
- всегда модель из настроек.

## 5. Служба на домашнем сервере (Mac mini)

Схема: всё работает на сервере (репозитории, исполнители, логины, ключи), ноутбук только открывает панель.

```bash
# на сервере
tailscale ip -4                                   # например 100.101.102.103
npm run build
node dist/server/serve.js --host 100.101.102.103  # проверить вручную
node dist/server/serve.js --print-token           # токен доступа
node dist/server/serve.js --host 100.101.102.103 --install-launchd
launchctl load -w ~/Library/LaunchAgents/dev.orchestra.serve.plist   # автозапуск при входе
```

Лог службы: `~/Library/Application Support/Orchestra/logs/serve.log`.

С ноутбука откройте `http://100.101.102.103:7777/?token=<токен>`. Токен запомнится в браузере, дальше хватит адреса без него.

Чтобы сервер не засыпал: `sudo pmset -a sleep 0 disksleep 0`. В «Системных настройках» включите «Перезапуск после сбоя питания» и автоматический вход пользователя, иначе launchd-агент не стартует после перезагрузки.

Всё, что нужно исполнителям, ставится **на сервер**: Claude Code с выполненным входом, Codex, ключи провайдеров (в настройках Orchestra), SSH-ключи для git, CodexBar. Порт 7777 не пробрасывайте в интернет.

Репозитории держите на локальном диске сервера или на внешнем диске, подключённом к нему (APFS). Для рабочих репозиториев не подходят exFAT и сетевые папки (SMB): там ломаются блокировки файлов и права доступа, а скорость падает.

## 6. Подключение ИИ-агентов через MCP

### Кто может оркестрировать

Оркестратором, то есть тем, кто планирует, раздаёт задачи и проверяет diff, может быть любой ИИ-агент, который умеет MCP. Исполнители от этого не зависят: они всегда одни и те же.

| Кто оркестрирует | Как подключается | Что нужно |
|---|---|---|
| **Claude Code** (подписка Claude Pro или Max) | Сама Orchestra запускает `claude` и даёт ему MCP-инструменты. Либо вы сами в терминале или в Orca: `claude mcp add` (ниже, вариант А) | Вход в `claude`. Модель по умолчанию, Opus (сильнее, быстрее тратит лимит) или Sonnet (экономнее) выбирается в «Настройках» |
| **Codex CLI** (подписка ChatGPT) | То же самое через `codex exec` и `codex mcp add`. Режим экспериментальный | `codex login`. Модель задаётся в «Настройках» |
| **Claude API** | Цикл оркестратора внутри самой Orchestra, по ключу | Подключение «Claude API». Модель по умолчанию `claude-opus-5` |
| **Cursor, агенты в Orca и любой клиент с MCP по HTTP** | Адрес `http://<сервер>:7777/mcp?repo=…` и заголовок `Authorization: Bearer <токен>` (ниже) | Работающая служба `orchestra serve` |

**Какие модели используются.** Исполнитель это headless Claude Code, которого Orchestra направляет на адрес провайдера (`ANTHROPIC_BASE_URL`). Поэтому подходит любой провайдер с Anthropic-совместимым API. В списке подключений есть готовые:

| Подключение | Модель по умолчанию | Роли по умолчанию | Цена за 1M токенов (вход / выход) |
|---|---|---|---|
| DeepSeek | `deepseek-v4-pro` (малая: `deepseek-flash`) | тесты, рефакторинг, документация | $1,32 / $3,96; вне часов пик вдвое дешевле |
| GLM (z.ai) | `glm-5.3` (малая: `glm-5.3-flash`) | фичи, багфиксы, рефакторинг | $1,4 / $4,4 |
| Kimi (Moonshot) | `kimi-k3` | фичи, багфиксы, тесты | по тарифу провайдера |
| MiniMax | `MiniMax-M3` | тесты, рефакторинг, документация | $0,3 / $1,2 |
| Qwen (Alibaba) | `qwen3-coder-plus` | фичи, багфиксы, тесты | $1 / $5 |
| OpenRouter | любая, например `deepseek/deepseek-v4-pro` | на ваш выбор | по цене выбранной модели |
| GLM и MiniMax по coding-плану | как выше | как выше | фиксированная плата, расход в кредитах плана |
| Claude через API-ключ или агрегатор | `claude-sonnet-5` | фичи, багфиксы, ревью | по тарифу провайдера |

Цены указаны для справки и меняются у провайдеров; точные значения лежат в карточке подключения, их можно поправить. Любой другой Anthropic-совместимый адрес добавляется как «Своё подключение». Роли можно менять в карточке.

Служба даёт MCP по адресу `http://<сервер>:7777/mcp`, с заголовком `Authorization: Bearer <токен>`.

**Вариант А: агент сам оркестратор.** Адрес с `?repo=`: агент получает инструменты `list_workers`, `delegate`, `wait_for`, `task_status`, `get_diff`, `merge_task`, `discard_task`, `end_session`.

```bash
cd /путь/к/проекту
claude mcp add --transport http orchestra "http://100.101.102.103:7777/mcp?repo=$(pwd)" \
  --header "Authorization: Bearer <токен>"
```

Путь в `repo` должен быть путём **на сервере**. Сессия видна в веб-панели вживую и потом в «Истории».

**Вариант Б: автопилот.** Инструменты `autopilot_start(goal, repo)`: Orchestra сама выбирает модель, планирует и ведёт задачу. Если в настройках стоит «спрашивать меня», ответ содержит рекомендацию и `pending_id`, дальше `autopilot_approve(pending_id)`, затем `run_status(run_id)`. Подходит для слабых клиентов и для телефона.

**Без службы**, один клиент на одной машине:

```bash
claude mcp add orchestra -- node /путь/к/Orchestra/dist/mcp/server.js
codex mcp add orchestra -- node /путь/к/Orchestra/dist/mcp/server.js
```

## 7. Вместе с Orca

[Orca](https://github.com/stablyai/orca) показывает терминалы и worktree, Orchestra распределяет задачи и считает деньги. Как они сочетаются:

- Orca-сервер и служба Orchestra работают на одном Mac mini, ноутбук подключается к обоим через Tailscale.
- В терминале Orca запускаете Claude Code, подключённый к MCP Orchestra с `?repo=<worktree этого терминала>`. Он становится координатором, а исполнители работают через Orchestra.
- **Один координатор на один worktree.** Два агента, сливающие в одну папку, мешают друг другу. Слияния Orchestra идут по очереди, но правки самого координатора в той же папке ломают слияние.
- Один терминал Orca не держите открытым одновременно на двух компьютерах (известная ошибка Orca с двумя десктоп-клиентами).
- Агенты Orca на подписке Claude и оркестратор Orchestra тратят один и тот же лимит. Следите по карточке подписки.
- **Память и wiki уходят вместе с коммитом.** После `orchestra-memory init` в репозитории правила лежат в `CLAUDE.md` и `AGENTS.md`, поэтому агенты в терминалах Orca сами смотрят память перед задачей, закрывают микросессии и обновляют wiki. Кнопки коммита и push в Orca запускают git-хуки репозитория: `.memory/`, `wiki/` и `CHANGELOG.md` попадают в тот же коммит. Если push остановился со словами «память дописана отдельным коммитом», нажмите push ещё раз. Подробно: [MEMORY.md](MEMORY.md).

## 8. Бюджеты и расходы

- **Бюджет на запуск** (Настройки → Оркестратор) считается в долларах по API: исполнители с оплатой за токены плюс оркестратор в режиме API.
  - при 80% оркестратор получает предупреждение;
  - при 100% исполнители останавливаются (их diff сохраняется), новые задачи не выдаются, оркестратор должен свернуть работу;
  - при 125% запуск останавливается.
- **Лимит на исполнителя**: при превышении он останавливается и больше не получает задач.
- **Подписки и coding-планы** в долларах стоят $0. Панель показывает, сколько это стоило бы по API (строка «подписки и планы по ценам API»).
- Расход оркестратора по API уменьшает кэширование промпта: за каждый следующий ход платите только за новую часть.

## 9. Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| Подписка Claude 🔴 «вход не выполнен» | На этой машине выполните `claude`, затем `/login`. |
| Codex 🔴 «вход не выполнен» | `codex login`. Некоторые планы ChatGPT (например, K-12 Teachers) Codex CLI не распознаёт. |
| 🔴 «не установлен», хотя программа есть | Приложение или launchd не видит PATH. Укажите полный путь в «Путь к Claude Code» или «Путь к Codex CLI» (`which claude`). |
| 🔴 «адрес или модель не найдены» | Неверный id модели или адрес на карточке. |
| 🟡 у DeepSeek, GLM и других | Пополните баланс, затем «Проверить». |
| «Нет ни одного работающего воркера» | Ни у одного подключения с «брать задачи» нет зелёного огонька. |
| «В репозитории есть незакоммиченные изменения» | Закоммитьте или сделайте `git stash`: исполнители ответвляются от последнего коммита. |
| Запуск «остановлен»: лимит подписки исчерпан | Дождитесь сброса окна или выберите другую модель, затем «Продолжить» в «Истории». |
| Слияние не удалось, конфликт | Ветка цела. Оркестратор обычно сам ставит задачу на исправление; вручную: слейте ветку сами или «Отбросить». |
| Веб-панель просит токен | `node dist/server/serve.js --print-token` и откройте `/?token=…`. |
| После перезагрузки сервера служба не работает | Проверьте автоматический вход пользователя и `launchctl list \| grep orchestra`, смотрите лог `serve.log`. |

## 10. Английский режим: подготовка окружения

Интерфейс Orchestra и весь процесс работы могут идти по-английски. Что сделать после переключения:

**1. Переключите язык.** Нажмите кнопку `RU` в шапке панели (она станет `EN`). Интерфейс переводится автоматически; выбор сохраняется и в настройках службы (`language`), поэтому модели пишут планы, брифы и отчёты по-английски, а память проекта (журнал, выжимки, сообщения хуков) следует за ним. Уже написанное (цели запусков, логи, старые записи журнала) остаётся как было.

**2. Обновите проекты.** Правила, которые Orchestra кладёт в `CLAUDE.md` / `AGENTS.md` проекта, команда `/orchestra` и стартовые страницы wiki существуют на обоих языках. После переключения откройте **Диагностику**: проекты, у которых правила на другом языке, покажутся устаревшими; примените обновление (или выполните `orchestra-memory init` в проекте). Закрепить проект за одним языком независимо от переключателя: `orchestra-memory init --lang en` (или `ru`), значение сохранится как `language` в `.memory/config.json`.

**3. Принципы Карпатого (глобально).** Диагностика показывает «Принципы Карпатого» для `~/.claude/CLAUDE.md`. Примените один раз: четыре принципа (думай до кода, простота прежде всего, хирургические правки, от цели) запишутся на текущем языке между маркерами, остальной файл не тронется. Те же принципы есть в блоке правил каждого проекта.

**4. RTK (короче вывод команд, меньше токенов).** RTK сжимает вывод команд оболочки до того, как его прочтёт модель; по нашим замерам он сэкономил около 90% токенов на выводе команд.
```
brew install rtk       # или см. https://www.rtk-ai.app/
rtk init -g            # добавит хук и RTK.md в ~/.claude (Claude Code)
rtk --version && rtk gain
```
Диагностика показывает «RTK» зелёным, когда хук включён. Orchestra сама переносит хук исполнителям, поэтому их вывод тоже сжимается. Правила проекта объясняют агентам, что делать, если вывод RTK выглядит неверно (`rtk proxy <команда>` для сырого результата).

**5. Фразы владельца.** Хуки распознают две фразы, по-русски или по-английски, в любом проекте: **«утверждаю» / «approve the brief»** (утверждает последний полный бриф `/orchestra`) и **«разрешаю прод» / «allow prod»** (открывает короткое окно для команд к проду; «запрещаю прод» / «revoke prod» закрывает). Создать такие разрешения сами агенты не могут.
