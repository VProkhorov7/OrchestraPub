# Gemini в Orchestra через мост: инструкция по шагам

**Зачем.** Воркеры Orchestra — это Claude Code, а он говорит только на языке Anthropic. Gemini на нём не говорит. Мост (программа LiteLLM) работает у вас на компьютере и переводит запросы туда и обратно. Для Orchestra Gemini после этого выглядит как обычный дешёвый воркер. Ведущим по-прежнему остаётся Claude.

```
Orchestra → воркер (Claude Code) → мост на вашем Mac (127.0.0.1:4000) → Google Gemini
```

**Что нужно:** Mac с Python 3 (проверка: в Терминале `python3 --version`), интернет, аккаунт Google.

**Что проверено, а что нет.** Проверено: установка, запуск моста, защита паролем и то, что запрос доходит до Google. Не проверено на реальном ключе: ответ модели, вызовы инструментов Claude Code и потоковая передача через Gemini. Поэтому шаг 10 — пробная задача, а не боевая.

---

## Шаги

### 1. Получите ключ Gemini
1. Откройте https://aistudio.google.com/apikey и войдите в аккаунт Google.
2. Нажмите «Create API key», затем скопируйте ключ (длинная строка, начинается обычно с `AIza`).
3. Не показывайте ключ никому и не вставляйте в чаты.

Бесплатный тир есть у `gemini-3.8-flash`, но он **очень маленький**: при проверке 01.10.2026 Google ответил «limit: 20» запросов в сутки на модель (`GenerateRequestsPerDayPerProject-FreeTier`). Одна задача воркера — это десятки запросов, так что бесплатного лимита хватит только на проверку моста. Для реальной работы подключите оплату в Google AI Studio (Billing → «Set up billing»): Flash тогда стоит копейки. У `gemini-3.1-pro-preview` бесплатного тира нет совсем. Условия бесплатного тира по использованию ваших данных Google'ом прочитайте сами, прежде чем отдавать туда закрытый код.

### 2. Откройте Терминал
Нажмите ⌘+Пробел, наберите «Терминал», Enter.

### 3. Перейдите в папку Orchestra
Скопируйте целиком (кавычки обязательны, в пути есть пробелы) и нажмите Enter:
```
cd "~/Developer/Orchestra"
```

### 4. Установите мост (один раз)
```
bash scripts/gemini-bridge/install.sh
```
- Ждите 1–3 минуты, идёт скачивание.
- Когда попросит, вставьте ключ из шага 1 (⌘+V). Текст не отображается, это нормально. Нажмите Enter.
- В конце напечатается строка вида `sk-...`. Это **пароль моста**. Скопируйте его для шага 8. Потеряли — выведите снова: `grep LITELLM_MASTER_KEY ~/orchestra-gemini-bridge/.env`

Ошибка про `python3` — установите Python с https://www.python.org/downloads/ и повторите шаг 4.

### 5. Запустите мост
```
bash scripts/gemini-bridge/start.sh
```
Через ~20 секунд появятся строки про «Uvicorn running on http://127.0.0.1:4000». **Это окно закрывать нельзя: пока оно открыто, мост работает.** Остановить: Ctrl+C.

### 6. Проверьте мост
Откройте **второе** окно Терминала (⌘+N), выполните шаг 3, затем:
```
bash scripts/gemini-bridge/test.sh
```
- В ответе есть текст модели → всё работает, идите дальше.
- `API key not valid` → ключ Gemini вставлен неверно. Откройте `~/orchestra-gemini-bridge/.env`, поправьте `GEMINI_API_KEY=` и перезапустите мост (Ctrl+C, затем шаг 5).
- `Connection refused` → мост не запущен, вернитесь к шагу 5.
- `quota` / `429` → закончился бесплатный лимит (20 запросов в сутки). Сброс в полночь по тихоокеанскому времени (в Москве около 10–11 утра). Либо подключите оплату.
- `context_management` / `UnsupportedParamsError` → в `config.yaml` моста нет строки `drop_params: true`. Скопируйте свежий файл: `cp scripts/gemini-bridge/config.yaml ~/orchestra-gemini-bridge/config.yaml`, затем перезапустите мост (Ctrl+C и шаг 5).

### 7. Откройте Orchestra
Запустите приложение и перейдите: **Настройки → Подключения**.

### 8. Добавьте Gemini Flash
1. В выпадающем списке выберите **«Своё (Anthropic-совместимый API)»**, нажмите «Добавить».
2. На новой карточке нажмите «Настроить» и заполните:

| Поле | Значение |
|---|---|
| Название | Gemini Flash (мост) |
| Адрес | `http://127.0.0.1:4000` |
| Ключ | пароль моста из шага 4 (`sk-...`) |
| Модель | `gemini-3.8-flash` |
| Цена входа / выхода за 1M | `0.75` / `3.75` (на бесплатном тире реально $0) |
| Роли | `docs`, `tests` |
| «брать задачи» | включить |

3. Нажмите «Проверить». Карточка должна стать 🟢.

Красная с «нет связи» — мост не запущен (шаг 5). «Модель не найдена» — проверьте поле «Модель».

### 9. По желанию: добавьте Gemini Pro
Повторите шаг 8 ещё раз, но: название «Gemini Pro (мост)», модель `gemini-3.1-pro`, цены `2` / `12`, роли `refactor`, `feature`. Для него нужна оплата в Google (шаг 1). Включайте только для сложных задач.

### 10. Дайте пробную задачу
Поставьте безобидную задачу вроде «добавь комментарий в README» с воркером Gemini Flash. Посмотрите результат (дифф) до слияния. Если инструменты не работают (воркер «зависает» или пишет про ошибки формата), остановитесь и сообщите: это может быть несовместимость моста, её нужно чинить, а не обходить.

---

## Каждый день
1. Откройте Терминал, шаг 3.
2. `bash scripts/gemini-bridge/start.sh` и оставьте окно открытым.
3. Работайте в Orchestra как обычно. Закончили — Ctrl+C.

## Безопасность
- Мост слушает только `127.0.0.1`: снаружи (из сети) к нему не подключиться.
- Ключи лежат в `~/orchestra-gemini-bridge/.env` (права 600), вне репозитория и в git не попадают.
- Версия LiteLLM закреплена: **1.82.6**. Версии 1.82.7 и 1.82.8 были заражены в марте 2026 (воровали ключи), поэтому скрипт ставит строго 1.82.6 и проверяет отсутствие файла `litellm_init.pth`. Не обновляйте LiteLLM самостоятельно (`pip install -U`).
- Если когда-нибудь ставили LiteLLM без закрепления версии в марте 2026 — смените все ключи, которые были на этом компьютере.
