# Orchestra

[English](README.md) · **Русский**

**Сильная модель руководит, дешёвые пишут код.** Orchestra ставит Claude (или ChatGPT) на роль ведущего инженера: он разбивает задачу на части, пишет подробные брифы, раздаёт их дешёвым моделям-исполнителям (DeepSeek, GLM, Kimi, MiniMax, Qwen), проверяет каждый diff и сливает в ваш репозиторий только то, что прошло ревью.

```
вы ── задача ──▶ оркестратор (Claude / ChatGPT, по подписке или API)
                   │ выбирает, кто планирует · составляет план · раздаёт задачи
                   ▼
   ┌──────────────┬──────────────┬──────────────┐
   │ DeepSeek     │ GLM план     │ Kimi …       │   каждый в своём git worktree и ветке
   │ тесты        │ фича         │ багфикс      │   (headless Claude Code)
   └──────┬───────┴──────┬───────┴──────┬───────┘
          ▼              ▼              ▼
   оркестратор читает diff → сливает / отбрасывает / просит исправить → запускает тесты → отчёт
```

## Зачем

- **Дёшево.** Планирование и ревью делает сильная модель, чаще всего по подписке, то есть без оплаты за токены. Код пишут модели, которые стоят в 10–50 раз дешевле.
- **Безопасно для репозитория.** Каждая задача идёт в отдельном worktree на своей ветке. В основную ветку попадает только то, что оркестратор проверил, а при конфликте ветка остаётся целой.
- **Под контролем.** Бюджет на запуск и лимит на каждого исполнителя (работает во время задачи, а не после неё), светофор по каждому подключению, история всех запусков с возможностью продолжить прерванный.

## Возможности

| | |
|---|---|
| **Обзор** | Главная вкладка: окошко с живым состоянием каждого идущего проекта (статус, исполнители, расход, последняя строка работы). Проектов может быть несколько, наблюдение не тратит токены. |
| **Выбор планировщика** | Для каждой задачи дешёвая модель оценивает сложность и рекомендует, кто будет планировать: Claude Opus или Sonnet, ChatGPT, API. Вы утверждаете или выбираете сами. |
| **Оркестратор по подписке** | Claude Pro/Max через Claude Code или ChatGPT через Codex CLI, без API-ключа. Либо Claude API. |
| **Подключения со светофором** | Добавляются из выпадающего списка. 🟢 работает, 🟡 подключено, но нет денег или исчерпан лимит, 🔴 не подключено. Показываются баланс DeepSeek и лимиты подписок (через CodexBar). |
| **Роли исполнителей** | Фичи, багфиксы, тесты, рефакторинг, документация, ревью. Каждому исполнителю разрешены свои роли. |
| **Бюджеты и лимиты** | Лимит на запуск и на исполнителя, расход по реальным токенам и ценам провайдера. Если цен нет, берётся живая оценка, чтобы лимит всё равно сработал. На подписках показывается, сколько работа стоила бы по API. |
| **Льготное время** | Исполнители с почасовым тарифом (DeepSeek: вдвое дешевле вне часов пик, с учётом праздников Китая) работают вместе в дешёвом окне; в часы пик задача уходит исполнителю без такого тарифа или ждёт. Запуск можно отложить до ближайшего дешёвого окна. |
| **Режим «только бесплатное»** | Одна кнопка вверху: платные исполнители и оркестратор по API-ключу отключаются; остаются локальные модели, бесплатные тарифы, бесплатные модели OpenRouter и уже оплаченные подписки. |
| **Локальные модели** | Ollama, LM Studio, llama.cpp или vLLM как бесплатные воркеры на вашем компьютере. Orchestra проверяет сервер, модель и длину контекста (Claude Code нужно 32K, а у Ollama на Mac с 16 ГБ по умолчанию 4K) и исправляет одной кнопкой. |
| **Сторожа и оповещения** | Служба сообщает о молчащем воркере, пропавшей рабочей папке, запуске у бюджета, упавшей задаче и подключении, которое перестало работать: колокольчик в панели, уведомление macOS, при желании webhook. Внешний сторож перезапускает службу, если она перестала отвечать. |
| **Автоповтор** | Упавшая задача перезапускается на другом подходящем исполнителе до трёх раз; если не помогло, оркестратор спрашивает вас, что делать, с историей попыток и вариантами. |
| **История** | Каждый запуск сохраняется. Прерванный можно продолжить с того же места, ветки сохранённого можно слить или отбросить позже. |
| **Служба `orchestra serve`** | Веб-панель, MCP по HTTP для любого ИИ-клиента, JSON API. Одна служба на домашнем сервере, доступ с ноутбука через Tailscale. |
| **MCP** | Claude Code, Codex, Cursor, агенты в Orca могут сами оркестровать исполнителей Orchestra или отдать задачу целиком в автопилот. |
| **Диагностика и режимы** | Проверка всего окружения и переключение «Orca и Orchestra вместе / только Orca / только Orchestra» с просмотром изменений и отменой. |
| **Память проекта** | В каждом репозитории: wiki для людей, журнал микросессий, база фактов и база решений с причинами, подробный JSON-лог всех действий, CHANGELOG по этапам. Перед задачей агенты смотрят, что уже сделано и почему. Память заводится сама при первом обращении к репозиторию или ветке, без `init`, и уходит в git с каждым коммитом. Подробно: [docs/MEMORY.md](docs/MEMORY.md). |
| **Русский и английский** | Одна кнопка переключает интерфейс (автоперевод) и весь процесс: правила для агентов, команду `/orchestra`, wiki, журнал, сообщения хуков, планы и отчёты моделей. В правила входят принципы Карпатого и RTK (короткий вывод команд). |
| **Светлая и тёмная тема** | По системе, по времени суток или фиксированная. |

## Быстрый старт

Нужны: macOS или Linux, Node.js 20+, git и [Claude Code](https://docs.claude.com/en/docs/claude-code) (`claude`, в нём выполнен вход).

```bash
git clone https://github.com/VProkhorov7/OrchestraPub.git
cd Orchestra
npm install
npm start            # настольное приложение
# или
npm run serve        # служба: веб-панель + MCP, адрес и токен будут в консоли
```

Дальше: **Настройки → Подключения**. Добавьте подписку Claude, чтобы был оркестратор, и хотя бы одного исполнителя с ключом, например DeepSeek. Подождите, пока оба загорятся зелёным. Затем выберите репозиторий, опишите задачу и нажмите **«Распределить автоматически»**.

Подробная инструкция (установка на домашний сервер, подключения, MCP, Orca, решение проблем): **[docs/SETUP.md](docs/SETUP.md)**. Настройка и ежедневная работа в Orca с памятью проекта: **[docs/ORCA.md](docs/ORCA.md)**. Техническое описание: **[docs/TECHNICAL.md](docs/TECHNICAL.md)**. Все документы: **[docs/README.md](docs/README.md)**.

## Кто может оркестрировать и на каких моделях

Оркестратором может быть **Claude Code** (подписка Claude Pro или Max), **Codex CLI** (подписка ChatGPT, экспериментально), **Claude API** или любой клиент с MCP, например Cursor или агент в Orca. Исполнители это headless Claude Code, направленный на дешёвого провайдера: DeepSeek (`deepseek-v4-pro`), GLM (`glm-5.3`), Kimi (`kimi-k3`), MiniMax (`MiniMax-M3`), Qwen (`qwen3-coder-plus`), OpenRouter или любой другой Anthropic-совместимый API. Полная таблица с ролями и ценами: [docs/SETUP.md](docs/SETUP.md#6-подключение-ии-агентов-через-mcp).

## Подключение к ИИ-агенту через MCP

```bash
# Claude Code в папке проекта, служба на Mac mini:
claude mcp add --transport http orchestra "http://mac-mini:7777/mcp?repo=$(pwd)" \
  --header "Authorization: Bearer <токен>"
```

После этого в агенте можно написать: *«Раздай эту задачу исполнителям Orchestra, проверь их diff и слей»* или *«Отдай задачу автопилоту Orchestra»*.

## Если оркестратор не запускается

Проверьте по порядку:

1. Подключение включено, и его светофор зелёный (веб-панель, раздел подключений).
2. Выполнен вход в Claude Code (запустите `claude` и при необходимости выполните `/login`).
3. Есть хотя бы один работающий исполнитель, которому можно делегировать задачи.

## Статус

Версия 0.7.5, личный инструмент, в активной разработке. Все сценарии покрыты автотестами (`npm run smoke`), где подписки и модели заменены заглушками. Проверки на реальных аккаунтах описаны в [HANDOFF.md](HANDOFF.md). Планы развития: [ROADMAP.md](ROADMAP.md).

**Безопасность:** исполнители работают на вашей машине без запросов разрешений (в отдельных worktree, но с доступом к shell). Не открывайте порт службы в интернет: используйте localhost или Tailscale. Orchestra не хранит и не использует токены подписок, она запускает официальные `claude` и `codex`, в которые вы вошли сами.
