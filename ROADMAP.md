# Orchestra: куда растём

Сейчас Orchestra это надёжный конвейер: Claude планирует, дешёвые модели пишут код в изолированных worktree, Claude ревьюит и сливает, всё сохраняется, бюджет под контролем, есть MCP-вход для Claude Code и Codex. Следующий шаг: превратить конвейер в «пульт управления командой», где видно, кто что делает, где система сама учится, кому что поручать, и где дешёвые воркеры используются так, как дорогие себе позволить не могут.

Главная идея, которая делает продукт интересным: **воркеры дешёвые, поэтому их можно тратить щедро**. Дать одну задачу трём моделям и выбрать лучший diff, прогонять ревью дешёвой моделью до того, как смотрит Claude, перезапускать с текстом упавшего теста. У Anthropic-only агентов это дорого, у Orchestra почти бесплатно.

## Как понимать, что стало лучше

Три числа, которые приложение будет считать по истории запусков и показывать на главном экране:

- **$ за слитую задачу** (всё, что потрачено, делённое на количество merged).
- **Доля слитого без переделок** (задача слита с первого раза, без fix-задачи и без discard).
- **Доля оркестратора в расходах**. Если Claude съедает больше 40% бюджета, значит он слишком много читает сам и мало делегирует.

Каждая фича ниже оценивается по тому, какое из этих чисел она двигает.

## v0.4 «Видно и надёжно»

**Живая доска.** Вместо ленты транскрипта: граф задач из плана (зависимости стрелками), карточки воркеров с тем, что они делают прямо сейчас, таймлайн параллельной работы, $ и токены на каждой карточке. Клик по карточке открывает diff с подсветкой, прямо в нём можно оставить комментарий, и он превращается в fix-задачу для того же воркера.

**Тестовый шлюз.** В настройках проекта команда тестов. После каждого воркера она запускается в его worktree автоматически, до того как diff попадает к Claude. Красные тесты: воркер получает вывод и одну попытку исправить. Claude видит только «зелёное» или «не справился за 2 попытки». Двигает долю без переделок и снижает расходы оркестратора.

**Режимы вывода.** Кроме слияния в локальную ветку: одна ветка на весь запуск с PR в GitHub (описание PR пишет Claude из финального отчёта), либо PR на каждую задачу.

**Подтверждение слияний.** Переключатель «спрашивать перед merge»: Claude предлагает слить, человек жмёт «да» или пишет, что не так.

**CI для самого Orchestra.** GitHub Actions гоняет `npm run smoke` на macOS и Linux на каждый push.

## v0.5 «Команда учится»

**Таблица воркеров.** По всей истории: для каждого провайдера и роли процент слитых задач, переделки, средняя цена и время. Видно, например, что DeepSeek отлично пишет тесты за $0.04, а фичи у него сливаются в 50% случаев.

**Маршрутизация по данным.** Эта таблица подаётся планировщику и оркестратору вместо текстовых заметок «хорош в тестах». Роли в настройках остаются как жёсткие ограничения, а внутри них выбор делается по статистике. Чем больше запусков, тем точнее.

**Турнир (best-of-N).** Для задач с пометкой «важно» или после неудачи: одна задача уходит 2–3 воркерам параллельно, дешёвый ревьюер сравнивает diff'ы, Claude выбирает победителя. Результаты турниров тоже идут в таблицу.

**Дешёвый первый ревьюер.** Роль «Ревью кода» становится обязательным этапом: GLM или Qwen читает diff первым и пишет замечания, Claude получает diff вместе с замечаниями и тратит меньше токенов на поиск очевидных проблем.

**Память проекта** (основа сделана в 0.6, см. [docs/MEMORY.md](docs/MEMORY.md)). Дальше: повторяющиеся замечания Claude на ревью («не используй any», «тесты лежат в `__tests__`») собираются и предлагаются для добавления в правила проекта для воркеров одним кликом.

## Следующее «Работает без тебя»

**Подготовка worktree.** Команда настройки проекта для worktree воркеров (как в Orca: `npm ci`, копирование `.dev.vars` и других неотслеживаемых файлов).

**Задачи из GitHub Issues.** Метка `orchestra` на issue запускает прогон с бюджетом по умолчанию, в конце появляется PR со ссылкой на issue.

**Расписание.** Ночные прогоны: обновить зависимости и починить сломанное, поднять покрытие тестами, разобрать TODO.

**Песочница.** Воркеры в Docker-контейнере вместо `--dangerously-skip-permissions` на твоей машине: сеть только к API провайдера, файловая система только worktree. Обязательно, прежде чем запускать задачи из чужих issue.

**Несколько запусков сразу** и несколько репозиториев в одном окне.

## v1.0 «Продукт»

Подписанный .dmg и автообновление, мастер первого запуска (проверка Claude Code, ключей и цен провайдеров за одну минуту), экспорт отчёта о запуске, английский интерфейс рядом с русским.

## Открытые вопросы

1. **Для кого.** Личный инструмент или продукт для других? От ответа зависит, что важнее: песочница и онбординг (для других) или турниры и статистика (для себя).
2. **Кто главный оркестратор.** Если основной сценарий это MCP из Claude Code по подписке, то доска и история должны уметь показывать MCP-сессии вживую, а собственный цикл приложения становится вторичным.
3. **Где жить данным.** Сейчас всё локально в userData. Для командного режима нужна общая история, а значит сервер.
