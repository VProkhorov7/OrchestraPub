# Changelog

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Added
- В инструкции и README: кто может оркестрировать (Claude Code, Codex CLI, Claude API, любой MCP-клиент) и какие модели используются исполнителями, с ролями и ценами (`docs/SETUP*.md`, раздел 6).
- Один настоящий лаунчер для рабочего стола вместо двух разрозненных файлов: `scripts/desktop/Orchestra.command` (запуск / перезапуск / остановка), три переходника ставит `install.sh`. Служба всегда под launchd; лаунчер сам находит репозиторий, пересобирает, чинит файл агента при переезде папки, открывает панель в уже открытой вкладке (Яндекс, Chrome, Brave, Edge и др.) и закрывает своё окно. Перезапуск не трогает службу, пока идут задачи воркеров. Новая команда `orchestra-ctl up | restart [--force] | stop | status | url`.
- README и документация на двух языках: `README.md` (English) и `README.ru.md`, `docs/SETUP.en.md`, `docs/MEMORY.en.md`, индекс `docs/README.md`, текст для страницы репозитория `docs/ABOUT.md`.
- Весь процесс по-английски при переключении на EN: правила для агентов в `CLAUDE.md`/`AGENTS.md` (с принципами Карпатого и RTK), команда `/orchestra`, стартовые страницы wiki, журнал и выжимки, сообщения хуков и сторожа прода, глобальный блок Карпатого в `~/.claude/CLAUDE.md`. Фразы владельца работают на обоих языках («approve the brief», «allow prod»). Проект можно закрепить за языком: `orchestra-memory init --lang en|ru`. Подготовка окружения: `docs/SETUP.md`, раздел 10.
- Язык отчётов моделей следует переключателю RU/EN: план, брифы, итоговый отчёт оркестратора, оценка сложности и выжимки пишутся на выбранном языке (`language` в настройках службы; по умолчанию ru).
- Переключатель языка RU/EN в шапке: английский — автоматический перевод (DeepSeek, около 400 фрагментов, `renderer/i18n-en.js`), подменяется на лету; тексты оркестратора, логи, diff и брифы не переводятся.
- Светлая тема и кнопка выбора в шапке: «как в системе» / «по времени суток» (светлая 07:00–19:00) / «светлая» / «тёмная»; выбор помнится в браузере.
- Вкладка «Обзор» (главная): по окошку на каждый идущий запуск — проект, статус, воркеры, расход, последняя строка работы; сетка до 2×2, клик открывает запуск. Читает уже приходящие события, токены не тратит.
- `scripts/collect-stats.mjs`: снимок статистики (tasks.csv, summary.json, копия serve.log по дням) в `<userData>/stats/`; запускается раз в час через launchd.

### Changed
- Тариф DeepSeek учитывает государственные праздники Китая (в документации: «кроме праздников»): 1–7 октября 2026 льготно целиком, и льготное окно в плашке тянется до 8 октября. Праздники 2027 внесены предварительно (только дни, где сходятся два прогноза), официальное расписание Госсовета выходит в ноябре 2026 — сверить. В плашке льготного времени теперь день недели, если окно кончается не сегодня.
- «В льготное время»: исполнители с почасовым тарифом (сейчас только DeepSeek и DeepSeek Flash) работают в общем окне, когда дёшевы все сразу; в часы пик задача такого исполнителя уходит к другому платному исполнителю без тарифа (подходящая роль, лимит не выбран, дешевле по цене выхода), а если такого нет — ждёт окна. Принудительный маршрут не подменяется.
- Диагностика «Орка и Orchestra» умещается на один экран; таблица проектов прокручивается внутри.
- Панель адаптивна: на узких окнах (до 1000 и до 760 px) колонки перестраиваются, горизонтальной прокрутки нет.
- Каждому платному API-подключению без лимита при загрузке настроек ставится лимит $3 за запуск (явный 0 — без лимита).

### Fixed
- Обзор и верхняя плашка: открытая MCP-сессия без задач больше не считается «идёт»; плашка считает все идущие запуски, а не только открытый на экране.
- Лимит `maxUsdPerRun` не работал для подключений без цен: стоимость в ходе задачи считалась нулём. Теперь без цен берётся живая оценка по прайсу Anthropic, и лимит останавливает задачу вовремя.

## [0.7.5] - 2026-09-29

### Removed
- Подключение «OmniRoute (локально)»: провайдеры шлюза подключаются через личные входы в подписки (Kimi, Antigravity и другие), что нарушает их условия и грозит блокировкой аккаунта. Карточка, добавленная в 0.7.4, удаляется из настроек при запуске.

## [0.7.4] - 2026-09-29

### Added
- Подключение «OmniRoute (локально)» для пробы: локальный шлюз к многим провайдерам как ещё один исполнитель — только документация и тесты, обязательно конкретная модель (не «auto»), понятное сообщение, если шлюз не запущен.

## [0.7.3] - 2026-09-28

### Added
- Принципы Карпатого (думать до кода, простота, хирургические правки, работа от цели): в правилах проектов, в задании исполнителям и — через диагностику, с возможностью отменить — в глобальном `~/.claude/CLAUDE.md` для всех проектов.
- Диагностика показывает RTK: установлен ли, включён ли хук, сколько токенов сэкономлено.

### Fixed
- Исполнители Orchestra со своей папкой настроек получают хук RTK владельца: их вывод команд тоже сжимается.

## [0.7.2] - 2026-09-28

### Added
- Запуск «В льготное время»: Orchestra стартует в ближайшее дешёвое окно исполнителей с почасовой ценой (DeepSeek вне часов пик вдвое дешевле), окно не короче трёх часов. Отложенные запуски видны в панели, их можно отменить или запустить сразу; переживают перезапуск службы.
- В таком запуске задачи исполнителя с почасовой ценой не начинаются в часы пик, а ждут их окончания; остальные исполнители работают как обычно.
- Индикатор тарифа в верхней строке: «DeepSeek: льготно до …» или «дорого до …».
- Автопилот через MCP принимает `when: "offpeak"`, инструмент `tariff_status`.

### Changed
- Расход исполнителей считается по тарифу в момент работы, а не по дневной цене.

### Fixed
- Поля цен и бюджета принимают любые дроби; цены DeepSeek — с официальной страницы; ссылка «настроить» в блоке подключений работает; диагностика не считает «изменёнными» файлы с выключенным учётом прав.

## [0.7.1] - 2026-09-28

Приёмы из практики коллег и проекта Skaro — механизмами, а не правилами в тексте.

### Security
- Сторож прода: выкладка, команды с `--remote`, секреты воркеров, запуск workflow и push, который выкладывает прод, выполняются только после фразы владельца «разрешаю прод».
- Исполнители Orchestra работают без ключей к проду и без входа в Cloudflare; сторож их не пускает никогда.

### Added
- Бриф из `/orchestra` сохраняется файлом и проверяется командой `orchestra-memory brief check`; утверждение владельца («утверждаю») привязано к версии брифа.
- `wiki/INVARIANTS.md` — что не должно стать неправдой; исполнители и проверка diff работают по нему.
- Роли агентов с закреплённой моделью: `scout` (дешёвая разведка), `applier`, `reviewer`.
- Отчёт исполнителя из четырёх частей: что сделано, почему, риски, как проверено.
- Реальное время и длительность микросессии в каждом запросе к агенту.

### Changed
- Журнал: «почему» обязательно для значимых записей; тип `cleanup` для ручной чистки без устранения причины.
- Передача смены: не больше трёх обязательных пунктов и ровно одна следующая задача.
- Правила для агентов: сначала разбор, потом работа; лечить причину; «готово» только с фактом; честный отчёт — последним блоком.
- Диагностика обновляет набор Orchestra в проектах (правила, сторож, команда, роли, инварианты) с возможностью отменить.

## [0.7.0] - 2026-09-28

### Added
- Диагностика и режимы работы Orca и Orchestra: «вместе», «только Orca», «только Orchestra». Перед применением показывается, что изменится; последнее изменение можно отменить.
- Файл `Orchestra.command` для запуска двойным кликом и команда `orchestra-doctor`.
- Вкладка «Диагностика» в панели: проверки системы, службы, подключений и всех проектов.
- Команда `/orchestra` в проектах: задача ставится по порядку — память проекта, бриф, утверждение владельцем, затем исполнители Orchestra, автопилот или сам Claude.

### Changed
- Новый внешний вид панели: тёмный «пульт управления» с верхней панелью статуса запуска и режима, шагами в боковой панели и карточками воркеров со временем, стоимостью и токенами.

### Fixed
- Проекты, у которых при переносе на другой диск сменились только права файлов, больше не выглядят изменёнными (диагностика предлагает исправить).

## [0.6.0] - 2026-09-27

### Added
- Память проекта в самом репозитории: wiki, журнал микросессий, база фактов и база решений с причинами, подробный JSON-лог всех действий.
- Команда `orchestra-memory`: контекст к задаче, поиск, факты, решения, закрытие микросессии, свежая выжимка, CHANGELOG по этапам, push вместе с памятью.
- Git-хуки: память и wiki уходят в каждый коммит, перед push недостающая память оформляется отдельным коммитом.
- Хуки Claude Code: память подмешивается к каждому запросу, правки файлов пишутся в лог, напоминание закрыть микросессию через 35 минут, автоматическое закрытие.
- Orchestra ведёт память во время запусков: оркестратор, планировщик и воркеры получают память к задаче, итоговый отчёт становится записью в журнале.
- Блок «Память» в панели: включить память, свежая выжимка, CHANGELOG этапа; MCP-инструменты памяти для любых агентов.
